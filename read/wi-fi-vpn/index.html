公衆Wi-FiでVPNが繋がらないときの切り分け手順

結論

公衆Wi-FiでVPNが繋がらないときは、ネットワーク接続 → captive portal（利用規約同意画面） → VPNプロトコル/ポート → DNS → プロキシ/ファイアウォールの順で切り分ける。多くの場合、同意画面が未完了か、Wi-Fi側が特定のポートをブロックしていることが原因になる。企業VPNはIT管理者、個人VPNはプロトコル変更で解決することが多い。

理由

  • 公衆Wi-Fiは利用規約同意が完了するまで外部通信を遮断する。同意前はVPN接続も失敗する。
  • ホテル・空港・カフェのアクセスポイントはセキュリティのため一部ポートを閉じている。VPNプロトコルによっては通らない。
  • DNSがWi-Fi提供者のものになり、社内サイトの名前解決が失敗することがある。
  • VPNクライアントのサーバー名・認証情報の入力ミスも原因になる。
  • 電波状態や混雑で接続がタイムアウトすることもある。

手順

1. Wi-Fi接続を確認する。ブラウザで任意のサイトを開き、表示されるか確かめる。表示されなければWi-Fi自体が未接続。

2. captive portalを確認する。ブラウザで `http://neverssl.com` にアクセスする。利用規約同意画面が出たら同意する。HTTPSではなくHTTPで確認するのがポイント。

3. 同意後に `https://www.google.com` が開けるか確かめる。

4. VPNクライアントのエラーメッセージを記録し、一度切断してから再接続する。

5. プロトコル/ポートを確認する。企業VPNはIT部門指定の設定を使う。個人VPNはOpenVPN（UDP）がブロックされる場合、TCPやWireGuardへの切替を試す。クライアントの設定画面の「プロトコル」欄で変更する。

6. DNSを確認する。VPN接続後に社内サイトが開けない場合、VPNのDNS設定を確認する。Windowsなら `ipconfig /all` でDNSサーバーを確認し、`nslookup` で名前解決をテストする。

7. プロキシ/ファイアウォールを確認する。企業PCのプロキシ設定がVPNと競合することがある。ブラウザのプロキシ設定を確認する。

8. スマホのテザリングでVPNが繋がるか試す。繋がればWi-Fi側の制限が原因と判断できる。

9. 接続失敗時のログを保存し、IT部門またはVPN提供者に共有する。

注意点

  • 失敗例: captive portal未完了のままVPN接続を試行し、タイムアウトになる。まずブラウザで同意画面を完了する。
  • 失敗例: ホテルWi-FiでOpenVPNのUDPがブロックされ接続失敗になる。TCPへの変更で解決する場合があるが、すべての環境で通るわけではない。変更前にIT部門または提供者に確認する。
  • 失敗例: VPN接続中なのにDNSがWi-Fi側のままになり、社内サイトが開けない。VPN設定で「DNSをVPN経由」を有効化する。
  • 失敗例: 企業PCのプロキシ設定がVPNと競合する。企業PCではIT管理者の指示に従う。
  • 注意: 公衆Wi-Fiでは通信が傍受される可能性がある。VPN接続が確立するまで機密情報を送らない。
  • 注意: 無料Wi-FiのSSID偽装に注意する。正規のSSIDを店舗に確認する。
  • 注意: テザリングはデータ容量を消費する。プランを確認する。
  • ポート番号やプロトコル名は一般的な例である。実際の設定はVPN提供者またはIT部門の指定に従う。確認方法: クライアントの設定画面、提供者のマニュアル、IT部門の案内。
